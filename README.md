# 数控刀具寿命闭环

统一记录数控刀具从入库、装刀、加工、调拨、修磨到报废的生命周期。
刀具身份与机床刀位分离，任何调拨都不重置累计加工证据——这正是断刀事故的
根因防线。

## 核心机制

- **事件溯源 + 哈希链**：所有操作只追加到 `data/…jsonl`，事件含 `seq`、
  `prev_hash`、内容哈希与业务幂等键。状态完全由重放得到，进程重启无分叉；
  任何篡改在重放时以 `TamperDetected` 暴露。
- **三类寿命独立核算**：件数 `part_count`、切削时长 `cutting_seconds`、
  异常冲击 `impact_score`。主轴负载按规则阈值分级（正常/预警/冲击，
  持续高载也算冲击），只把冲击折算进 `impact_score`。
- **生效期明确的规则版本**：规则按 零件×材料 发布，带 `valid_from/valid_to`
  与内容哈希，区间不可重叠、不可改写；开工授权时锚定当时生效的版本，
  成品追溯精确到“哪把刀 + 哪版规则 + 哪张授权”。修磨后件数/时长定额按
  `grind_factor` 折减，冲击定额不折减。
- **合法状态迁移**：`available → mounted → warning → blocked →
  grinding/retired`，换刀、调拨、修磨、报废、孪生接管在写入与重放两处
  都强制校验。调拨事件携带计数快照，重放时比对，防止“重置寿命”。
- **开工授权四结论**（`domain_contract.json`）：
  `allowed` / `finish_current_cut`（预警后仅允许一次收尾切削）/
  `denied`（越过硬上限，持人工放行单也不放行）/ `manual_review`
  （无生效规则等异常，须工程师签字放行）。
- **幂等**：扫码回执、装/卸刀、调拨单据、复核单据都有业务幂等键，
  重复扫码原样返回、绝不二次计数。
- **离线补报隔离**：旧机床迟到回执只生成复核单（`late_report_quarantined`），
  工艺主管签字 accept 后消耗才入账并标注来源 `late_review`；身份存疑的
  补报只能 reject。
- **孪生刀接管**：预警/封锁刀具由班组长从待换刀队列触发，旧刀合法离位、
  孪生刀走 `available → mounted` 接管同一刀位，旧授权全部作废、自动换发
  新授权；两把刀寿命各自独立。
- **角色边界**：操作工只处理扫码/回执；班组长只看待换刀队列并触发换刀、
  接管、修磨、报废；工艺主管发布规则、复核定案、成品追溯、签发范围+限期
  +HMAC 签字的人工放行。
- **修磨语义**：件数/切削时长随新刃口清零，冲击疲劳跨刃口保留。

## 目录

```
app/domain.py      状态机、阈值、规则、区间判定
app/events.py      append-only 事件日志、哈希链、幂等键、flock、重放
app/signing.py     范围化人工签字（HMAC-SHA256，可替换为非对称证书）
app/projection.py  全量重放投影（只读模型，二次校验所有迁移与签字）
app/service.py     用例服务层（授权、回执、调拨、复核、接管、修磨、放行）
app/demo.py        端到端生命周期演示（含进程重启指纹比对）
tests/             需求级测试
```

## 运行

```bash
python -m unittest discover -s tests -v   # 35 个需求级测试
python -m app.demo --clean                # 全生命周期演示（生成 data/demo_log.jsonl）
python -m app.demo --verify data/demo_log.jsonl   # 独立进程只读重建并打印指纹
```

演示覆盖：建账与两版规则 → 在线加工与负载分级 → 重复扫码去重 →
机床间调拨（计数保留）→ 旧机床离线补报隔离 → 签字复核（接受/驳回）→
规则换版 → 预警收尾/硬限封锁/拒绝新开工 → 待换刀队列 → 孪生刀接管换发
授权 → 修磨清零与定额折减 → 范围化人工放行（越权被拒）→ 成品与事故
追溯 → 销毁内存状态后子进程重放，逐字节比对 head 哈希与状态指纹。
